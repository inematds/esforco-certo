En resumen

Esfuerzo justo es un kit gratuito para quienes usan Claude Code en proyectos y robots. Lee la configuración, los agentes y los scripts de tu proyecto y muestra con qué modelo (Fable, Opus, Sonnet, Haiku) y esfuerzo funciona cada cosa. El esfuerzo es cuánto piensa el modelo antes de responder, en una escala de cinco niveles: low < medium < high < xhigh < max. Señala lo que cuesta de más, incluye una regla lista para pegar en tu CLAUDE.md y una prueba que ejecuta el mismo trabajo con dos esfuerzos, usando tu suscripción, para que compares. Necesitas Python 3 y, para la prueba, Claude Code; la auditoría no usa internet ni API.

Qué es

Tres herramientas para no pagar de más

La propia Anthropic, al lanzar Fable 5.2 (9/11/2026), recomienda empezar con Opus 5.5 y pasar a Fable solo para el trabajo más difícil. El kit convierte ese consejo en algo que puedes aplicar y comprobar.

🔎 Auditoría con 1 comando

auditar.py revisa la configuración, los agentes, las skills, los scripts, los timers y el código que llama a la API; muestra qué partes fijan el modelo y el esfuerzo. Advierte si Max está fijo, si Xhigh está como predeterminado o si Fable está como predeterminado.

📋 Regla lista + agentes

politica/CLAUDE-esforco.md es el bloque para pegar en CLAUDE.md. En agentes/ vienen tres agentes listos: uso diario (Opus, medium), trabajo largo (Fable, high) y tareas mecánicas (Haiku, low).

⚖️ Prueba A/B con tu suscripción

ab.sh ejecuta la misma solicitud con dos o más combinaciones de modelo y esfuerzo, y arma un cuadro con el tiempo, los tokens, el costo equivalente, el modelo que se usó de verdad y si la prueba pasó.

Los números

En la prueba de código, Max hizo menos y costó 3×

FrontierCode 2.0 mide si quienes mantienen proyectos abiertos aceptarían el código del modelo. Valores leídos en la gráfica de costo por tarea de la página de Anthropic (pruebas de la propia empresa).

1

Fable · high

45,3% por ~US$ 7 por tarea. Empata con el mejor resultado de Opus 5.5 por cerca de la mitad del costo.

2

Opus 5.5 · max

45,5% por ~US$ 13 por tarea: la mejor nota de Opus, con el esfuerzo más alto. (Para el uso diario, Anthropic recomienda Opus; la regla del kit usa medium.)

3

Fable · xhigh

49,1% por ~US$ 15. La nota más alta entre los modelos lanzados que Anthropic probó.

4

Fable · max

~45,7% por ~US$ 45: menos que xhigh, con cerca de 3× el costo. Por eso Max no es el predeterminado.

Dos cosas a tener en cuenta. Con esfuerzo medium, Fable queda unos 3 puntos por encima de Opus por el mismo costo; y en otra prueba (diseño de hardware) el mejor resultado salió con Max. La regla no es "nunca Max", sino "Max solo después de medir". Además, toda la tabla de resultados corresponde al esfuerzo más alto disponible, mientras que Claude Code viene con medium: esos resultados no reflejan lo que tú usas.

Cómo funciona

Audita, define la regla, mide y fija el estándar

Nada cambia automáticamente: el kit lee y sugiere; tú decides si cambias el modelo o el esfuerzo.

auditar.py→ Leer las alertas→ Pegar la regla en CLAUDE.md→ ab.sh mide en tu trabajo→ Elegir el predeterminado→ --estrito en CI
Requisitos previos

Qué necesitas

Linux, macOS o WSL. La auditoría funciona por sí sola; la prueba A/B usa Claude Code con tu suscripción iniciada.

Python 3.8+

Para auditar.py (solo usa la biblioteca estándar).

# comprobar
python3 --version

Claude Code

Para ab.sh: el comando claude en el PATH y la sesión iniciada con tu suscripción.

# comprobar
claude --version

git

Para descargar el kit y para el modo --editar de la prueba (una copia del proyecto por combinación).

# comprobar
git --version
Guía de uso · paso a paso

Del inicio al estándar justo en 8 pasos

Reemplaza ~/meu-projeto por la carpeta de tu proyecto.

1

Descarga el kit

Un repositorio pequeño: dos scripts, la regla, tres agentes y el plan de resets de Fable (qué es un reset: paso 8).

git clone \
  https://github.com/inematds/esforco-certo.git
cd esforco-certo
2

Audita tu proyecto

Primero, haz una prueba sin riesgo en el proyecto de ejemplo que viene con el kit (muestra 8 alertas a propósito). Después, revisa tu proyecto: la lista muestra cada lugar donde se fija el modelo o el esfuerzo, con archivo y línea. --home incluye tu ~/.claude (configuración, agentes y skills globales) y los timers de systemd del usuario.

python3 auditar.py tests/fixture      # ejemplo del kit
python3 auditar.py ~/meu-projeto \
  --home                             # tu proyecto
python3 auditar.py ~/meu-projeto \
  --json > aud.json                  # para que lo lea otro script
3

Lee las alertas

MAX: esfuerzo max fijo; cámbialo por high (o xhigh si al medir ves una mejora). PADRAO_ALTO: xhigh como predeterminado global o para un modelo; cada solicitud paga el costo más alto. FABLE_PADRAO: Fable como modelo predeterminado; consume el límite más rápido. Las sugerencias muestran robots con claude -p sin --model (heredan el predeterminado de la cuenta); una sugerencia no es una alerta y no hace que falle --estrito.

# dónde cambiar el modelo predeterminado de Claude Code (ejemplo)
# solo en esta sesión:
claude --model opus --effort medium
# o en .claude/settings.json: "model": "opus", "effortLevel": "medium"
4

Pega la regla en CLAUDE.md

Opus medium para el uso diario, Fable high para el trabajo largo, xhigh solo después de medir, nunca Max como predeterminado, robots siempre con --model y --effort.

cat politica/CLAUDE-esforco.md \
  >> ~/meu-projeto/CLAUDE.md
5

Usa los agentes listos

Claude Code elige el agente según la descripción; cada uno ya incluye el modelo y el esfuerzo en el encabezado.

mkdir -p ~/meu-projeto/.claude/agents
cp agentes/*.md ~/meu-projeto/.claude/agents/
# guarda la regla y los agentes en un commit (el paso 6 usa el último commit)
cd ~/meu-projeto && git add CLAUDE.md .claude/agents \
  && git commit -m "modelo e esforço: regra e agentes"
cd -
6

Mide antes de cambiar de modelo

Sin -c, ejecuta tres combinaciones: opus:high, fable:medium y fable:high (dos con Fable, que consume el límite más rápido). Sin --editar, cada ronda solo lee el proyecto. Con --editar, cada combinación trabaja en una copia propia del último commit (git worktree); por eso el proyecto debe estar limpio, sin cambios pendientes. --checar ejecuta tu prueba dentro de cada copia. La copia no incluye carpetas fuera de git (node_modules, .venv): instala las dependencias dentro de --checar. El cuadro muestra el tiempo, los tokens, el modelo que se usó de verdad y el costo equivalente: el precio según la tabla de la API; con tu suscripción pagas con el límite, no en dólares. Empieza con una tarea pequeña y real.

./ab.sh "Revisa src/ y enumera los 5 riesgos más graves" \
  --dir ~/meu-projeto
./ab.sh "Corrige la prueba rota en tests/" \
  --dir ~/meu-projeto --editar \
  --checar "npm ci && npm test" \
  -c opus:high -c fable:high
# resultado: ~/meu-projeto/.ab/resultado-<data>/RESULTADO.md
# (agrega .ab/ al .gitignore del proyecto)
7

Fija la regla en CI (opcional)

Con --estrito, el auditor termina con código 1 si encuentra alguna alerta y falla el paso de CI. Así nadie deja Max o Fable como predeterminado por accidente. Copia auditar.py (un solo archivo, sin dependencias) a tu proyecto y ejecútalo en CI desde la raíz del proyecto; no se audita a sí mismo. Funciona en Linux y macOS (en macOS, ab.sh usa gtimeout de brew install coreutils, si está disponible).

mkdir -p ~/meu-projeto/tools
cp auditar.py ~/meu-projeto/tools/
# en el CI del proyecto (por ejemplo, un paso de GitHub Actions):
python3 tools/auditar.py . --estrito
8

Usa los resets de Fable en un trabajo largo

En la promoción de lanzamiento, válida hasta el 16/11/2026, quienes tienen una suscripción recibieron de 1 a 3 resets de Fable: cada reset vuelve a cero el contador de uso de Fable para que puedas seguir usándolo durante la misma semana. En los planes Pro y Team estándar, el uso de Fable puede ocupar hasta la mitad del límite semanal del plan. resets.md es la guía: elige un trabajo largo, prepáralo con Opus, ejecútalo con Fable high y ciérralo con Opus. Después del 16/11, la misma guía sirve para cualquier trabajo largo con Fable.

less resets.md
claude --model fable --effort high   # en la sesión del trabajo largo
Consejos · cómo pedir el nivel de esfuerzo

¿Se puede pedir el nivel de esfuerzo en lenguaje natural?

Depende de quién vaya a ejecutarlo. Pedirlo en la conversación no cambia el nivel de esfuerzo de la sesión en la que estás hablando; cambia el nivel de esfuerzo del trabajo que delegas.

1. En la sesión actual: comando

Escribir "usa esfuerzo alto" en la conversación no cambia nada: el modelo no cambia su propio nivel de esfuerzo. Usa el comando /effort (o /model para cambiar el modelo), o inicia la sesión directamente con ese nivel de esfuerzo.

/effort high
# o, al iniciar la sesión:
claude --model opus --effort high

2. Subagentes: lenguaje natural

Para el trabajo delegado, pedirlo en la conversación funciona. Claude pasa el modelo y el nivel de esfuerzo al subagente, y solo fija el nivel de esfuerzo cuando lo pides explícitamente; si no lo pides, se aplica el valor predeterminado del agente.

"haz la revisión con un subagente Opus en esfuerzo alto"
"ejecuta esta búsqueda en Haiku, esfuerzo bajo"

3. Regla fija: CLAUDE.md y agentes

Si lo escribes en CLAUDE.md, cuenta como una solicitud explícita en cada sesión, sin necesidad de repetirla. Los agentes con model: y effort: en el encabezado, como los tres del kit, ya se inician con el nivel de esfuerzo correcto.

# en CLAUDE.md
- revisiones: Opus en high
- tareas mecánicas: Haiku en low

4. Robots: opción en la línea de comandos

En claude -p, el nivel de esfuerzo se especifica únicamente con la opción --effort. Si no la incluyes, el robot hereda el valor predeterminado de la cuenta y auditar.py lo señala.

claude -p --model opus --effort medium \
  "resume el registro de hoy"

| haiku-low  | ok (claude-haiku-5-5)  | 12 s | 434 tokens |

En la primera versión, la prueba de solo lectura usaba el modo plan, y Claude Code cambió Haiku por Sonnet sin avisar. Por eso ab.sh muestra el modelo usado y marca "⚠ pidió X, ejecutó Y" cuando son diferentes.

Agente para trabajos largos

---
name: trabalho-longo
model: fable
effort: high
---

Antes de empezar, escribe el objetivo, el criterio para darlo por terminado y qué no debe hacer; prueba cada etapa y no sube a max por su cuenta.
