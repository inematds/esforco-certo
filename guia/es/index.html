En resumen

Esfuerzo justo es un kit gratuito para quienes usan Claude Code en proyectos y robots. Lee la configuración, los agentes y los scripts de tu proyecto y muestra con qué modelo (Fable, Opus, Sonnet, Haiku) y esfuerzo funciona cada cosa. El esfuerzo indica cuánto piensa el modelo antes de responder, de low a max. Señala lo que cuesta de más sin necesidad, incluye una regla lista para pegar en tu CLAUDE.md y una prueba que ejecuta el mismo trabajo con dos esfuerzos, usando tu suscripción, para que compares. Necesitas Python 3 y, para la prueba, Claude Code; la auditoría no usa internet ni API.

Qué es

Tres herramientas para no pagar de más por el nivel más alto

La propia Anthropic, en el lanzamiento de Fable 5.2 (9/11/2026), recomienda empezar con Opus 5.5 y subir a Fable solo para el trabajo más difícil. El kit convierte ese consejo en algo que puedes aplicar y comprobar.

🔎 Auditoría con 1 comando

auditar.py revisa la configuración, los agentes, las skills, los scripts, los timers y el código que llama a la API, y enumera qué fija el modelo y el esfuerzo. Alerta si Max está fijo, Xhigh es el valor predeterminado o Fable es el modelo predeterminado.

📋 Regla lista + agentes

politica/CLAUDE-esforco.md es el bloque para pegar en CLAUDE.md. En agentes/ vienen tres agentes listos: uso diario (Opus, medium), trabajo largo (Fable, high) y tareas mecánicas (Haiku, low).

⚖️ Prueba A/B con tu suscripción

ab.sh ejecuta el mismo pedido con dos o más combinaciones de modelo y esfuerzo, y arma un cuadro con el tiempo, los tokens, el costo equivalente, el modelo que realmente se ejecutó y si la prueba pasó.

Los números

En la prueba de código, Max hizo menos y costó 3×

FrontierCode 2.0 mide si quienes mantienen proyectos abiertos aceptarían el código del modelo. Valores leídos en el gráfico de costo por tarea de la página de Anthropic (pruebas de la propia empresa).

1

Fable · high

45,3% por ~US$ 7 la tarea. Empata con el mejor resultado de Opus 5.5 por cerca de la mitad del costo.

2

Opus 5.5 · mejor

45,5% por ~US$ 13 la tarea. Es el valor predeterminado que Anthropic recomienda para el uso diario.

3

Fable · xhigh

49,1% por ~US$ 15. La puntuación más alta entre los modelos lanzados que probó Anthropic.

4

Fable · max

~45,7% por ~US$ 45: menos que xhigh, con cerca de 3× el costo. Por eso Max no es el valor predeterminado.

Hay dos cosas que tener en cuenta. Con esfuerzo medium, Fable queda unos 3 puntos por encima de Opus por el mismo costo; y en otra prueba (diseño de hardware), el mejor resultado se obtuvo con Max. La regla no es «nunca Max», sino «Max solo después de medir». Además, toda la tabla de puntuaciones corresponde al esfuerzo más alto disponible, mientras que Claude Code viene con medium: esos resultados no reflejan lo que tú usas.

Cómo funciona

Audita, decide la regla, mide, fija

Nada cambia por sí solo: el kit lee y sugiere; tú decides si cambias el modelo o el esfuerzo.

auditar.py→ Leer las alertas→ Pegar la regla en CLAUDE.md→ ab.sh mide tu trabajo→ Elegir el valor predeterminado→ --estrito en CI
Requisitos

Qué necesitas

Linux, macOS o WSL. La auditoría funciona por sí sola; la prueba A/B usa Claude Code con la sesión iniciada en tu suscripción.

Python 3.8+

Para auditar.py (solo usa la biblioteca estándar).

# comprobar
python3 --version

Claude Code

Para ab.sh: el comando claude en el PATH y la sesión iniciada con tu suscripción.

# comprobar
claude --version

git

Para descargar el kit y para el modo --editar de la prueba (una copia del proyecto por combinación).

# comprobar
git --version
Guía de uso · paso a paso

De cero al valor predeterminado adecuado en 8 pasos

Cambia ~/meu-projeto por la carpeta de tu proyecto.

1

Descarga el kit

Un repositorio pequeño: dos scripts, la regla, tres agentes y el plan de resets.

git clone https://github.com/inematds/esforco-certo.git
cd esforco-certo
2

Audita tu proyecto

Enumera cada lugar que fija el modelo o el esfuerzo, con archivo y línea. --home incluye tu ~/.claude (configuración, agentes y skills globales) y los timers de systemd del usuario.

python3 auditar.py ~/meu-projeto --home        # informe Markdown en pantalla
python3 auditar.py ~/meu-projeto --json > aud.json  # para que lo lea otro script
3

Lee las alertas

MAX: esfuerzo max fijo; cámbialo por high (o xhigh, si al medir ves una mejora). PADRAO_ALTO: xhigh como valor predeterminado global o de un modelo; cada pedido paga el nivel más alto. FABLE_PADRAO: Fable como modelo predeterminado; consume el límite más rápido. Las sugerencias muestran robots con claude -p sin --model (heredan el valor predeterminado de la cuenta).

# dónde cambiar el valor predeterminado de Claude Code (ejemplo)
claude --model opus --effort medium   # solo en esta sesión
# o en .claude/settings.json: "model": "opus", "effortLevel": "medium"
4

Pega la regla en CLAUDE.md

Opus medium para el uso diario, Fable high para el trabajo largo, xhigh solo después de medir, nunca Max como valor predeterminado y robots siempre con --model y --effort.

cat politica/CLAUDE-esforco.md >> ~/meu-projeto/CLAUDE.md
5

Usa los agentes listos

Claude Code elige el agente según su descripción; cada uno ya incluye el modelo y el esfuerzo en el encabezado.

mkdir -p ~/meu-projeto/.claude/agents
cp agentes/*.md ~/meu-projeto/.claude/agents/   # dia-a-dia, trabalho-longo, mecanico
6

Mide antes de cambiar de modelo

Sin indicar combinaciones, ejecuta opus:high, fable:medium y fable:high. Sin --editar, cada ejecución solo lee el proyecto. Con --editar, cada combinación trabaja en una copia propia (git worktree) y --checar ejecuta tu prueba al final. Cada ejecución consume tu límite: empieza con una tarea pequeña y real.

./ab.sh "Revisa src/ y enumera los 5 riesgos más graves, con archivo y línea" --dir ~/meu-projeto
./ab.sh "Corrige la prueba que falla en tests/" --dir ~/meu-projeto --editar --checar "npm test" -c opus:high -c fable:high
# resultado: ~/meu-projeto/.ab/resultado-<data>/RESULTADO.md (agrega .ab/ a .gitignore)
7

Fíjalo en CI (opcional)

Con --estrito, el auditor termina con el código 1 si hay alertas. Así nadie fija Max o Fable como valor predeterminado sin querer.

python3 auditar.py . --estrito || echo "modelo/esfuerzo caro como valor predeterminado — consulta el informe"
8

Usa los resets de Fable en un trabajo largo

En la promoción de lanzamiento (hasta el 16/11/2026), quienes tenían una suscripción recibieron de 1 a 3 resets de Fable, y en los planes Pro y Team estándar Fable está disponible hasta con la mitad del límite semanal. resets.md es la guía: elige un trabajo largo, prepáralo en Opus, ejecútalo con Fable high y termínalo en Opus.

less resets.md
claude --model fable --effort high   # en la sesión del trabajo largo

Justo lo que la página de Anthropic recomienda evitar: el nivel más alto como valor predeterminado. 13 robots reciben el modelo mediante una variable que se lee de un archivo central de modelos (bien: se cambia en un solo lugar).

Prueba A/B: el modelo que realmente se ejecutó

| haiku-low  | ok (claude-haiku-5-5)  | 12 s | 434 tokens |
| sonnet-low | ok (claude-sonnet-5-5) | 16 s | 539 tokens |

En la primera versión, la prueba de solo lectura usaba el modo plan, y Claude Code cambiaba Haiku por Sonnet sin avisar. Por eso ab.sh muestra el modelo utilizado y marca «⚠ pidió X, ejecutó Y» cuando no coinciden.

Agente para trabajo largo

---
name: trabalho-longo
model: fable
effort: high
---

Antes de hacer cambios, escribe el objetivo, el criterio para darlo por terminado y qué no debe hacer; prueba cada etapa y no sube a max por su cuenta.
