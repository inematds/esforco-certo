In short

Right effort is a free kit for people who use Claude Code in projects and bots. It reads your project's settings, agents, and scripts and shows which model (Fable, Opus, Sonnet, Haiku) and effort each item runs on—effort is how much the model thinks before answering, from low to max. It points out what costs more than needed, gives you a ready-to-paste rule for your CLAUDE.md, and provides a test that runs the same task at two effort levels through your subscription so you can compare. You need Python 3 and, for the test, Claude Code; the audit does not use the internet or an API.

What it is

Three tools to avoid paying top rates unnecessarily

Anthropic itself, in the Fable 5.2 launch (Nov 9, 2026), recommends starting with Opus 5.5 and moving up to Fable only for the hardest work. This kit turns that advice into something you can use and verify.

🔎 Audit with 1 command

auditar.py scans settings, agents, skills, scripts, timers, and code that calls the API, and lists what fixes the model and effort. It flags fixed Max, Xhigh as the default, and Fable as the default.

📋 Ready-to-use rule + agents

politica/CLAUDE-esforco.md is the block to paste into CLAUDE.md. agentes/ contains three ready-made agents: everyday work (Opus, medium), long tasks (Fable, high), and mechanical tasks (Haiku, low).

⚖️ A/B test through your subscription

ab.sh runs the same request with two or more model and effort combinations and creates a table with time, tokens, equivalent cost, the model that actually ran, and whether your test passed.

The numbers

In the coding test, Max did less and cost 3× more

FrontierCode 2.0 measures whether people who maintain open source projects would accept the model's code. Values read from the cost-per-task chart on Anthropic's page (the company's own tests).

1

Fable · high

45.3% at about US$ 7 per task. Ties with the best Opus 5.5 result at about half the cost.

2

Opus 5.5 · best

45.5% at about US$ 13 per task. This is the default Anthropic recommends for everyday work.

3

Fable · xhigh

49.1% at about US$ 15. The highest score among the released models Anthropic tested.

4

Fable · max

~45.7% at about US$ 45: lower than xhigh, at about 3× the cost. That's why Max is not the default.

Two things to keep in mind. At medium effort, Fable scores about 3 points higher than Opus for the same cost; and in another test (hardware design), the best result came at Max. The rule is not "never Max"; it's "use Max only after measuring." And the entire score table uses the highest available effort, while Claude Code defaults to medium: those scores do not reflect what you run.

How it works

Audit, set the rule, measure, lock it in

Nothing changes automatically: the kit reads and suggests; you choose whether to change the model or effort.

auditar.py→ Read the alerts→ Paste the rule into CLAUDE.md→ ab.sh measures on your work→ Choose the default→ --estrito in CI

User guide · step by step

From zero to the right default in 8 steps

Replace ~/meu-projeto with your project folder.

1

Download the kit

A small repository: two scripts, the rule, three agents, and the reset plan.

git clone https://github.com/inematds/esforco-certo.git
cd esforco-certo
2

Audit your project

Lists each place that fixes a model or effort, with the file and line. --home includes your ~/.claude (global settings, agents, and skills) and the user's systemd timers.

python3 auditar.py ~/meu-projeto --home        # Markdown report on screen
python3 auditar.py ~/meu-projeto --json > aud.json  # for another script to read
3

Read the alerts

MAX: effort fixed at max—switch to high (or xhigh if you measure a benefit). PADRAO_ALTO: xhigh as the global or model default—every request pays the top rate. FABLE_PADRAO: Fable as the default model—uses up your limit faster. The tips point out bots that use claude -p without --model (they inherit the account default).

# where to change the Claude Code default (example)
claude --model opus --effort medium   # this session only
# or in .claude/settings.json: "model": "opus", "effortLevel": "medium"
4

Paste the rule into CLAUDE.md

Opus medium for everyday work, Fable high for long tasks, xhigh only after measuring, never Max as the default, and always use --model and --effort for bots.

cat politica/CLAUDE-esforco.md >> ~/meu-projeto/CLAUDE.md
5

Use the ready-made agents

Claude Code chooses an agent based on its description; each one already has the model and effort in its header.

mkdir -p ~/meu-projeto/.claude/agents
cp agentes/*.md ~/meu-projeto/.claude/agents/   # everyday, long-task, mechanical
6

Measure before switching models

Without specifying combinations, it runs opus:high, fable:medium, and fable:high. Without --editar, each run only reads the project. With --editar, each combination works in its own copy (git worktree), and --checar runs your test at the end. Each run uses your limit: start with a small, real task.

./ab.sh "Review src/ and list the 5 most serious risks, with file and line" --dir ~/meu-projeto
./ab.sh "Fix the broken test in tests/" --dir ~/meu-projeto --editar --checar "npm test" -c opus:high -c fable:high
# result: ~/meu-projeto/.ab/resultado-<data>/RESULTADO.md (add .ab/ to .gitignore)
7

Enforce it in CI (optional)

With --estrito, the auditor exits with code 1 if there are any alerts. That way no one accidentally sets Max or Fable as the default.

python3 auditar.py . --estrito || echo "expensive model/effort as default — see report"
8

Use Fable resets on a long task

During the launch promotion (through Nov 16, 2026), subscribers received 1 to 3 Fable resets, and on Pro and standard Team, Fable is included for up to half the weekly limit. resets.md is the playbook: choose a long task, prepare it in Opus, run it in Fable high, and wrap up in Opus.

less resets.md
claude --model fable --effort high   # in the long-task session

In the first version, the read-only test used plan mode, where Claude Code switched Haiku to Sonnet without saying so. That's why ab.sh shows the model used and marks "⚠ asked for X, ran Y" when they differ.

Long-task agent

name: trabalho-longo
model: fable
effort: high
---

Before making changes, it writes the objective, completion criteria, and what not to do; tests every step; and does not raise the effort to max on its own.
